本次更新：你首先应该看到什么

MindMap Builder 当前最重要的变化不是“多了几个按钮”，而是已经形成了 结构编辑层 + Markdown 交换层 + 任务层 + 自动化 API 层。 因此，它可以从普通思维导图升级为项目控制图、研究索引图和 Agent 执行界面。

官方源码确认：脚本使用持久侧栏，也可切换到浮动窗口；支持自动布局、递归分组、颜色、Pin、折叠、边界、子图，以及 Markdown 复制粘贴与交叉链接保留。

语法重点
关系:: 节点：把“关系”写到进入节点的箭头标签上。
#boundary：导入时给该节点的子树生成边界。

^blockId 与 [[#^blockId|*]]：保留非层级交叉链接。

来源说明：这些格式来自当前源码的解析器和导出器；不是普通 Markdown 的通用语法，而是 MindMap Builder 用于可逆交换的约定。

示意：普通树 + 子图 + 反馈回路

层级由 MindMap Builder 管理；返回箭头是普通 cross-link；复杂修复分支转成独立子图。

示意：Markdown 往返不是“纯文本丢失”

导出器会用专用 Markdown 元数据表达关系；再次导入时可重建多种结构。

任务、日历、优先级：把地图变成项目面板

当前源码支持 Toggle Checkbox Status 和 Task Calendar & Priority。日期类型包括 Due、Start、 Scheduled、Created、Done、Cancelled，并可保存优先级与 recurrence。
示意：任务节点

Tasks 插件存在时，脚本会读取其 taskFormat，并兼容 emoji 或 Dataview 字段。

建议用法

  1. 一级分支代表阶段：设计、构建、测试、发布。
  2. 叶子节点才转换为任务，避免每个分类标题都变成 checkbox。
  3. 高风险节点设置优先级和截止时间。
  4. 完成后折叠该分支，只保留阶段状态。
  5. 需要文本复盘时 Export Markdown。

边界：官方源码支持任务格式的读写与编辑，但没有说明它会与外部任务查询自动双向同步。更稳妥的理解是“可兼容地写入任务语法并手动往返”。

API 与 Agent：最新版最有潜力的部分

公开 API 的设计目标是让脚本和 AI Agent 不必重新实现布局算法，而是先发现能力、验证参数，再调用高层操作。

const mmb = window.MindMapBuilderAPI;
if (!mmb?.ready()) throw new Error("MindMap Builder API 未就绪");

// 先发现能力，再验证参数
const spec = mmb.spec();
const check = mmb.validate("addNode", {
  text: "运行回归测试",
  ontology: "验证",
  follow: true
});

if (!check.ok || !check.data.valid) {
  console.error(check);
  return;
}

const node = await mmb.addNode(check.data.normalizedArgs);
await mmb.refreshMapLayout(node.data?.nodeId);

Agent 安全执行顺序

1
ready / spec
确认运行时和当前能力。
2
validate
在执行前检查参数并取得 normalizedArgs。
3
addNode / importMarkdown / performAction
调用高层功能。
4
refreshMapLayout
统一重新排版。
5
getElementIdsByRole
按节点、分支箭头、交叉链接、边界等角色定向处理。
最强组合： MindMapBuilderAPI 负责“语义结构与布局”，ExcalidrawAutomate 负责“精细样式、几何变换、文件与场景操作”。

基于最新版能力的创新工作流

说明：以下是基于官方功能进行的工作流设计和推断，不是官方仓库直接给出的成品模板。

核心设计：用箭头 ontology 标注“负责、依据、验证、返回”；把错误恢复做成 Submap；把修复动作做成任务；测试失败通过普通 cross-link 返回专家审判。

Agent 反馈→顾问判断→修正方案→任务化执行→测试

先把论文笔记链接到节点，使用 Import Outline from Linked File 导入标题；每一章转成 Submap Root；主题群使用 Boundary；展示时 Fold 到一级。

价值：一张图既是目录，也是章节导航器；需要写作时再导出某一分支为 Markdown。

通过 ExcaliAI 的 Create Mindmap 任务，从图片或提示词生成 H1 + bullet 层级并导入；然后人工添加关系标签、边界、任务、子图与交叉链接。

原则：AI 负责“覆盖率”，人负责“层级正确性、因果关系和行动优先级”。

使用固定 ontology 词表，例如“依据、负责、产生、验证、阻塞、返回”；通过 setMapConfig 固定布局和样式；通过 Markdown 模板复制到新项目。

这样 Agent 可以读取 getNodeText 返回的 text + ontology，更容易理解地图语义，而不只是看到父子层级。

Agent 使用 getElementIdsByRole 分别取得 nodes、branchArrows、crossLinks、boundaries、decorations；检查是否存在孤立节点、过长文字、无标签反馈箭头或过度折叠，再用 ExcalidrawAutomate 标记问题。

适用：大型技术架构图、课程知识图、项目复盘图。

应用到你的 MCP 地图

推荐结构

  • 中心：完成 MCP 的部署和构建
  • 一级：执行方案、专家审判、Agent 自我修复、验证
  • Ontology：“依据”“负责”“触发”“返回”
  • Boundary：专家审判
  • Submap：Agent 自我修复
  • Tasks：修复动作与测试动作
  • Cross-link：测试失败 → 专家审判
不要把 “continue” 和 “fix the problem” 当普通说明。把它们做成带框的命令节点，并放在对应错误节点下面。

样式层面继续使用 Right-Left、多色一级分支、短节点文字、最后添加图片与说明卡。
